1ドキュメント情報

文書名ポケモンカード管理ツール 要件定義書
目的個人のポケモンカードコレクションを、セット単位で「持っている／持っていない」を管理するツールの要件を整理し、開発着手前の合意形成を行う。
対象読者開発担当（本人）
実運用者本人以外の担当者。使う人ごとに自分の端末で自分のコレクションを独立管理する（データは他者と共有しない・ログイン不要）。
関連資料TCGdex API（https://tcgdex.dev/）
前提無料の範囲で完結すること。サーバー費用・API利用料をかけない。

2背景・目的

手持ちのポケモンカードが増え、「どのカードを持っていて、どれが未所持か」を把握しづらくなっている。 パックを買う際やコレクションを整理する際に、セットごとの収集状況をひと目で確認できる手段が欲しい。

そこで、カード図鑑のようにセット単位でカードを一覧し、所有／未所有を塗り分けて管理できるツールを作成する。 相場の追跡や売買管理は行わず、「コレクションのコンプ状況の見える化」に目的を絞る。

達成したいこと

ゴール説明
収集状況の見える化セットごとに「何枚中何枚所持」のコンプ率が分かる。
登録の手軽さカード名や型番を手入力せず、カード画像を見ながらタップで所有登録できる。
コストゼロ運用無料APIとブラウザ内保存で、月額費用なしで動かせる。

3システム概要・構成

サーバーやデータベースを自前で構築せず、ブラウザだけで完結するWebアプリとして作る。 カードのマスタ情報（セット・カード名・番号・レアリティ・画像）は外部の無料API（TCGdex）を都度参照し、 「どのカードを所有しているか」という自分のデータだけをブラウザ内に保存する。

構成要素採用方針
形態PC優先のWebアプリ。スマホでも閲覧できるようレスポンシブ対応。
カードマスタTCGdex API（日本語）を都度参照。カードDBは自前で持たない。
所有データの保存ブラウザ内のローカル保存（IndexedDB / localStorage）。ログイン不要。
バックアップ / 端末移動JSONファイルで書き出し・読み込み。手動で別端末へ移せる。
技術想定フロントエンド完結（React もしくは 素のHTML/JS）。サーバー費用ゼロ。
配布方法無料の静的ホスティング（GitHub Pages / Netlify / Cloudflare Pages 等）にURL公開し、実運用者にはリンクを渡す。ZIP配布も可能だが、実運用ではURL公開を推奨。

実運用者への配布

本ツールは本人以外の担当者が実運用する。使う人ごとにデータは独立するため、同じアプリを複数人に配っても互いのコレクションは混ざらない。配布方法は次の2通り。

方法相手の手間備考
URL公開推奨リンクを開くだけ。スマホでも可。更新は差し替えるだけで全員に反映。実運用向き。
ZIP配布解凍してローカルで開く／簡易サーバー起動。環境により file:// でAPI通信・画像読込が動かない場合があり、サポートが煩雑。技術がわかる人向け。
Note — ローカル保存の性質 所有データはブラウザ内に保存されるため、ブラウザのデータ消去や別端末では引き継がれない。 この弱点は「JSONエクスポート／インポート」で補う。まずはPC1台での利用を主とし、スマホは閲覧・軽い登録に使う想定。

4機能一覧

初期リリースで実装する機能を示す。所有の管理は「持っている／持っていない」の2状態のみとし、所有枚数のカウントは行わない。

ID機能説明優先度
F-01セット一覧TCGdexの日本語セット（約177セット）を一覧表示。各セットの総枚数と所有コンプ率（例: 45/103）を表示する。必須
F-02セット詳細（図鑑ビュー）選んだセットのカードを番号順にグリッド表示。各カードは画像＋番号＋レアリティを表示し、タップ／クリックで所有をトグルする（所有＝カラー、未所有＝グレーアウト）。必須
F-03カード名検索カード名で横断的に検索し、ヒットしたカードから所有登録できる。必須
F-04コレクション集計総所有枚数、セット別コンプ率、レアリティ別の内訳を表示する。推奨
F-05データのエクスポート／インポート所有データをJSONで書き出し・読み込み。バックアップおよびPC⇄スマホのデータ移動に使う。必須
F-06絞り込み表示図鑑ビューで「未所有のみ」「所有のみ」を切り替え表示する。推奨

対象外（今回は作らない）

項目理由
資産価値・相場の追跡相場データのAPIは有料または不安定なため、目的（収集の見える化）から外す。
所有枚数のカウント「持っている／持っていない」で足りるため。管理をシンプルに保つ。
複数ユーザー・ログイン個人利用のため不要。
デッキ構築・売買管理本ツールのスコープ外。

6データ項目

以下はAPIから都度取得する参照情報。自分では保持しない。

項目説明TCGdexフィールド例
カードIDカードの一意ID（セット記号＋番号）SV1a-001
カード名日本語カード名name（トロピウス）
番号セット内の番号localId（001）
レアリティレアリティrarity（Common）
セット名所属セット名set.name（トリプレットビート）
画像カード画像URL（高解像度PNG）image + /high.png

所有データ（ブラウザ内に保存）

実際に自分で保持するのは、下記のシンプルな所有情報のみ。

項目説明
カードID所有しているカードのID（TCGdexのカードIDと一致）
所有フラグ持っている＝true。未所有のカードは保存しない（=falseと同義）。
Note — データ構造の考え方 所有データは「所有しているカードIDの集合」として保持すれば十分。所有枚数・状態・購入情報は今回のスコープ外。 将来これらを足す場合も、カードIDをキーに項目を追加する形で拡張できる。

7外部データ源（TCGdex API）

カードマスタは TCGdex の無料APIを利用する。事前検証で、必要な項目が日本語・無料・APIキー不要で取得できることを確認済み。

確認項目結果
提供元TCGdex（tcgdex.dev） / エンドポイント api.tcgdex.net
料金 / 認証無料・APIキー不要
日本語セット数約177セット（最新のメガシリーズまで対応）
取得できる項目カード名・番号・レアリティ・セット名・カード画像（高解像度PNG）
画像image URL に /high.png を付与して取得（HTTP 200 確認済み）
Note — 外部依存のリスク カードマスタを外部APIに依存するため、API側の仕様変更・停止時は影響を受ける。所有データ自体はローカルに残るため失われないが、 対策として「一度取得したセット／カード情報をブラウザにキャッシュする」ことを検討する。

8開発フェーズ

小さく動くものから作り、段階的に広げる。

PHASE 1コア（図鑑＋所有管理）
  • TCGdexからセット一覧・カード一覧を取得して表示（F-01, F-02）
  • カードのタップで所有トグル → ブラウザ内に保存
  • セットごとのコンプ率表示
PHASE 2検索・集計・データ管理
  • カード名検索（F-03）
  • コレクション集計・レアリティ別内訳（F-04）
  • JSONエクスポート／インポート（F-05）、絞り込み表示（F-06）
PHASE 3改善（任意）
  • 取得データのキャッシュ（オフライン閲覧・API依存の緩和）
  • スマホUIの最適化
  • 将来的な拡張（所有枚数・状態など）の検討
Phase 1 完了基準
好きなセットを開き、カードをタップして所有登録でき、コンプ率が表示される。再読み込み後も所有状態が残る。
Phase 2 完了基準
カード名で検索して登録でき、全体の集計が見られ、JSONでバックアップ・復元できる。

9設計上の仮定・意思決定ログ

項目内容
対象言語日本語カードを中心とする。
管理単位「持っている／持っていない」の2状態のみ。所有枚数はカウントしない。
データ保存まずはブラウザ内ローカル保存で開始。同期はJSONエクスポート／インポートで代替。
利用端末PCを優先。スマホは閲覧・軽い登録に対応。
実運用者・配布本人以外が実運用。無料の静的ホスティングにURL公開して配布（ZIPも可）。使う人ごとにデータは独立し、他者とは共有しない。
カードマスタ手入力マスタは作らず、TCGdex APIを都度参照する（無料で取得可能なことを検証済み）。
今後の検討事項 ・端末間でリアルタイムに同期したくなった場合のクラウド保存の要否
・TCGdexで対象カードが見つからない場合の手動追加の要否
・レアリティ表記（英語）を日本語ラベルに変換するかどうか

10用語集

用語意味
セット拡張パックなどの発売単位。カードは各セットに属する。
図鑑ビューセット内のカードを番号順に並べ、所有／未所有を塗り分けて表示する画面。
コンプ率そのセットの総枚数に対し、所有しているカードの割合（例: 45/103）。
TCGdexポケモンカードのマスタ情報を提供する無料の多言語API。本ツールのカードデータ源。
IndexedDB / localStorageブラウザ内にデータを保存する仕組み。所有データの保存先。
エクスポート／インポート所有データをJSONファイルとして書き出し・読み込みする機能。バックアップと端末移動に使う。
